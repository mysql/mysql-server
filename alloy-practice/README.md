# Alloyによる形式検証の実習

## 検証対象のOSS
本レポートでは，オープンソースのSQLリレーショナルデータベース管理システムであるMySQLを対象に検証を行った．MySQLは，データベース操作言語であるSQLを実用の上で扱えるように様々な機能を備えたRDBMSの一種である．ソフトウェアとしての規模が大きく，システム全般について考えるのは非常に困難なため，ごく基本的な次の2つの側面のみに抽象化して考えることとする．
* リレーショナルベース(以下RDB)に基づくデータベース操作
* ACID特性を満たすように設計されたトランザクション操作

本レポートにおいては，それぞれの観点別にモデル化しその性質を検証する．

## 検証すべき性質
### 1. MySQLのデータベース構造に関する性質
以下に，RDBの性質として検証すべき項目を列挙する．これらはリレーショナルデータベースにおける基本的な構造であるから、MySQLの仕様でも標準的に保証される．
1. 1. 一般的なRDBの性質
これらはリレーショナルデータベースにおける最も基本的でいかなるときも満たされるべき構造である．
- テーブルは，0個以上のレコード，フィールド，および値をもつ．
- レコードの値は、それぞれのフィールドに対応しており、テーブルの定義外のフィールドを参照しない

1. 2. 非NULL制約，主キー制約，外部キー制約の性質
RDBでは，テーブル生成時に任意でいくつかの制約と呼ばれる効果を付与できる．
(Alloyの検証における「制約」と混同しやすいが，RDBにおける「制約」は性質として捉えることができる．)
本レポートにおいては代表的な3つの制約を取り上げる．
- 「非NULL制約」は，値が欠損している(NULLである)セルを持つレコードおよびフィールドが存在してはいけないという制約である．
- 「主キー制約」は，各レコードを一意に識別できるキー(主キー)をテーブルに課すという制約である．キーはレコードを特定または関連付けるためのフィールドのことである．
- 「外部キー制約」は，一つのテーブルのフィールドが別のテーブルの主キー（または一意なキー）となるフィールドを参照するという制約である．


## モデル化
データベーステーブル(以下テーブル)は，一般的には行(レコード)と列（フィールド）からなる二次元配列として捉えられることが多い．今回モデル化するにあたってはテーブルを，固有のフィールド要素の集合，およびレコードの集合からなる構造体と捉える．
